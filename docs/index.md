# 5025 Robotics Wiki

This is the team's shared guide to how a competition robot works. Start with the big picture, then follow a system into operation, troubleshooting, or programming detail.

Start with the [robot system map](/systems/) to see how the major parts relate, or use the sidebar to enter through the system you are working on.

New to robot software? Follow the [new programmer path](/start/new-programmers). It moves from reading Java to making, testing, and reviewing a small robot-code change.

If the robot is not behaving correctly, use [Report a robot problem](/start/report-a-problem) to give programmers a clear GitHub issue without needing to diagnose the code yourself.

## What goes in the wiki

- Principles that apply across robots and seasons
- Safe operating, testing, and troubleshooting procedures
- Diagrams that explain relationships between hardware, software, and people
- Technical detail needed to understand why a system behaves the way it does

## What stays with the season code

Robot-specific constants, current controls, match strategy, and implementation notes belong in that season's robot project. Wiki pages may link to them as examples, but should not depend on them.

::: warning Keep pages reusable
Before adding a page, ask whether it would still help with a different robot. If not, put it in the season repository.
:::
